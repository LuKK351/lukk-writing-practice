# 工具使用

工具保护稿件、地图与记录，不代作教学判断。以下命令均指 `<Python> "<Skill>/scripts/practice.py" --root "<练习目录>" <命令>`；`<Python>` 代表连接时验证过的启动方式，不是让用户输入的字面命令；脚本路径、目录与文件参数均按当前终端正确引用。用户不需要运行命令或理解后台字段；完整参数见 `--help`。

| 操作 | 用法与边界 |
|---|---|
| 新练习 | 按开练规则明确起稿方式后，`new --title ... --label 从空白开始写初稿`建空稿；加`--draft "<临时目录>/本人原文.md" --label 导入已有原稿`原样导入。R01自动带待诊断地图与最后校对行，不生成诊断。建好回读实际稿件和R01，向用户给出稿件链接与下一步。 |
| 每轮回读 | `status Wxxx --read`只读返回R01、最新全文、地图、是否适用当前稿及read_token。AI须实际阅读；它不是自动评价。 |
| 更新约定 | `record Wxxx --read-token <本轮凭据> --input "<临时目录>/摘要.json"`；可用`--note "<临时目录>/过程.md"`替换当前解释。地图结果只能随review更新。 |
| 送评快照 | `submit Wxxx`返回sha256；同版可反复提交，保留历史反馈，不新建V。提交后再status --read取得写入前的最新上下文与凭据。 |
| 检阅与更新地图 | `review Wxxx --read-token ... --sha256 ... --input "<临时目录>/反馈.md" --summary "<临时目录>/摘要.json"`；summary显式给stage及完整training_map，不允许遗漏旧事项。 |
| 开始新修改阶段 | `next Wxxx --read-token ... --basis phase --label '调整回应与材料' --reason '完整初稿后开始实质修改'`；先保存并检阅当前稿，原样复制，保留地图。本人明确指定用`--basis user`；已结束练习只接受本人要求重开。 |
| 词句新阶段 | 按[记录规则](规则/记录.md#版本按修改阶段主动判断)确定集中修改后，先review保存内容稿与校对地图，再status --read取得新凭据，执行`next Wxxx --read-token ... --basis phase --cleanup --label '全文字词句校对' --reason '内容修改完成，进入集中词句修改'`。旧收益保留为版本记录，新对照基准是紧邻上一版；回读确认新稿后给入口，再请本人修改。已有校对工作版或符合沿用条件则不重复next。 |
| 正常结束 | `close Wxxx --read-token ... --version Vxx --reason '本人明确结束'`；采用稿精确快照已有反馈、地图已核验、必要及正在处理事项无遗留、最后全文校对已完成。 |
| 带遗留结束 | 只有本人明确选择才给close加`--allow-unfinished`，reason说明选择；页面标记带遗留结束，保留地图，不能写成全部完成。仍须采用稿已有反馈及当前地图。 |
| 查误改位置 | `status Wxxx`简要列出修改版本；不自动迁移。 |
| 恢复误改 | `recover Wxxx --version Vxx --into-current --reason ...`归入未改动的现有工作稿；确需另存时不用into-current并给label。两边都改则停，不覆盖。已结束篇不能recover重开。 |
| 刷新与核验 | `refresh Wxxx`按状态重绘R01；仅整理记录说明时可加`--input "<临时目录>/整理.json" --read-token ...`，已结束篇也可用，不重开。`index`重建导航，`check`只读核验稿件、历史反馈与地图结构；不证明教学判断正确。 |

新建练习时，目录名中的冒号、问号等 Windows 禁用标点会改为全角形式（路径分隔符和控制字符仍拒绝），末尾句点也会调整；文章标题和原文保持不变。版本说明不用文件名禁用字符，不自动重命名旧练习。

`new`不直接改选题库；按[开练规则](规则/开练.md)完成来源关联和移转。无库或直接来稿跳过。


## 连接 Obsidian 与同步菜单

所有资源从当前 Skill 的真实目录加载，个人目录没有规则或脚本副本。首次使用先确认 Agent 可读写文件、执行本地命令；按当前系统检查已有 Python 启动方式（如 `python3`、`python`、Windows 的 `py -3` 或解释器完整路径），不能把命令别名存在当成环境可用。

用选定的启动方式执行 `<Python> "<Skill>/scripts/init_workspace.py" --check-env`：确认 Python 3.10+，在系统临时目录实测中文／空格路径与 UTF-8 读写；结果给出解释器和临时目录。检查不创建练习、不更改绑定；首次连接选定库时仍会验证实际目录的读写权限。环境已核验且未变化时不重复安装或运行预检。

全文命令中的 `<Python>` 使用上述已验证启动方式；若使用解释器完整路径，须按当前 shell 的调用语法处理（PowerShell 的带引号可执行路径前需要 `&`）。`<临时目录>` 是系统临时目录内本轮专用子目录，使用 Python `tempfile.mkdtemp()` 或当前 Agent 提供的临时目录能力建立，不硬编码 `/tmp` 或盘符。输入 JSON、反馈和说明文件保存为 UTF-8；工具也接受这些输入文件的 UTF-8 BOM。完成后只清理本轮自行创建且不再需要的临时材料。

如果没有可用 Python 3.10+，按当前系统说明安装方式，在已有授权范围内协助安装并再次预检；不替换系统 Python，不让用户维护后台命令。没有本地文件／命令能力时说明限制，可先讨论，不声称已保存。工具直接读写笔记文件，不调用 Obsidian API，不要求插件或 CLI。Windows 完整实测尚未完成，不能把本机预检等同于跨平台验证。

环境就绪后，首次或跨窗口使用：

1. `<Python> "<Skill>/scripts/init_workspace.py" --inspect` 只读查看本机绑定与 Obsidian 已登记的库。
2. 有效绑定直接使用；没有绑定时承接当前写作意图，确认库及其下的练习文件夹，用户已给目录不再问。绑定失效先找回，不能另建空目录冒充原练习。
3. 首次绑定或明确换目录：`<Python> "<Skill>/scripts/init_workspace.py" --root "<目录>" --bind`。普通恢复及每轮带练不加 `--bind`，只核验目录和同步菜单。

可选 `--vault "<库目录>"` 明确上级库；默认向上寻找 `.obsidian`。检查证明库目录与文件可访问，不证明 Obsidian 界面已经显示新文件；不需要插件。首次初始化保留用户的目标目录，在其中逐项创建，文件回读成功后才写入初始化标记；中途失败保留现场并停止，不宣称完成或覆盖重建。

每轮开始再次运行初始化命令：保留现有稿件、记录、首页、选题库，核验读写权限并按 Skill 同步 `03 练习方法.md` 的内容。菜单不独立维护；Obsidian 自动调整的表格空格与横线长度不算内容差异，不因此阻塞或反复重写。文字、链接、列序及对齐方式改变仍须同步；status/check 保持只读。陌生非空目录、符号链接目标、失效绑定或核心目录缺失均先核对，不覆盖、不另建空系统。

绑定保存在 `~/.config/lukk-writing-practice/workspace.json`（设置 XDG_CONFIG_HOME 时遵循该配置目录）；不在 Skill 内。`--config <文件>` 仅用于明确指定另一份本机配置或隔离测试。初始化只生成 `01 开始练习.md`、`02 选题库.md`、`03 练习方法.md`、`00 我的练习` 文件夹及隐藏后台；不创建 AGENTS.md，不复制方法、规则、工具；替换或升级 Skill 不改变个人目录。`--inspect` 不创建目录、不开练、不换绑定。

初始化成功后回读 `entry_file` 指向的入口，向用户给出可点击的实际文件链接，并说明“00 我的练习”尚为空，选定题目后才建具体稿件。用户反映看不到时，先核对实际路径、文件与当前库；磁盘有文件但界面未收录时，在保存当前编辑后刷新／重新打开库，不重复初始化或重建文件。随后按开练规则给出通用的开始方式。

首次没有可检测的库时，请用户指定；若尚无库，在 Obsidian 中创建／打开后再连接。不扫描用户所有文档，不自动创建 `.obsidian` 来伪装连接。没有本地写入能力时说明限制，只做对话教学。

## 一轮怎样操作

已有练习先 `status --read` 并实际读 R01 与全文，再读当前节点规则及方法。只讨论且无结果变化无需写入；新练习先 new，再取得状态。

收到待检验稿：读全文 → submit → status --read → 对照约定并逐项核地图 → review → 告知结果和下一步。即使文字未变，作者选择或误诊纠正改变了地图，也对同一快照 review，不新建版本。record、review、next、close 各用自己写入前 status --read 的凭据；状态、页面或正文变化后重新读取。

常规建版前完整当前稿已保存并检阅；明确要求先另存的用户选择可用 basis=user，但不能据此宣称新旧稿已检验。所有建版先保证原稿有快照，next 复制正文；旧稿若带版本元数据，仅更新对应版本字段。

凭据只是上下文一致性保护，不能证明AI理解或检查充分。人工编辑R01后，status --read仍可读取；先理解，再record加`--accept-page-change --note "<临时目录>/合并说明.md"`接纳，旧页面自动备份。体会区原样保留。

## 地图数据（仅AI维护）

`training_map`包含purpose（本篇目的）、strengths（应保留之处数组）、items、proofread、checked_version、checked_sha256。新练习已初始化，先从status --read取得结构；review自动绑定当前稿件版本与sha256，不能用record将旧图标成已复核。

每项固定字段如下；文字保持短而具体，前台只展示四列，检验依据折叠：

```json
{
  "id": "P1",
  "level": "required",
  "kind": "content",
  "status": "active",
  "problem": "‘我换了队’没有前情，无法理解为什么换队",
  "action": "补入本人确实记得的换队原因",
  "check": "能从文字复述动作与原因，不增加虚构事实",
  "basis": "M01：必要前情让动作可理解；具体判断回到本稿",
  "result": ""
}
```

- level：required必须处理、optional可选优化。待确认用status，不另造第三等级。
- kind：content内容、language词句。最后完整校对的发现也列在同一items中；不是另一个库。
- status：pending待处理／待选择、selected本人已选待练、active进行中、clarify待确认、resolved已解决、kept保留、withdrawn撤回。最多一个content为active；最后全篇词句校对本身可处理多项。
- problem含原文锚点与影响；action是方向；check是同一检验标准；basis只说明书中工具的机制或一般语言依据，不混入进度。工具将同类型事项的相同basis合并展示一次，保留每项check；不同依据不推断为相同。result简记处理证据或本人选择，不重复完整版本收益。resolved／kept／withdrawn必须有result。
- 编号稳定，不重排复用、不静默删除；顺带解决写明原因，不冒称独立训练。必要项标kept仍算遗留；本人可明确带遗留结束。
- proofread格式为`{"status":"pending","note":""}`；完整校对后为checked，并在note说明通读范围、发现事项和复核结果。只有内容事项已处理、stage为wrap才能确认；checked不等于每一项已改完，close还会检查必要项。
- 同版新稿、换版后旧图均待复核。进入wrap要求必要／正在练的content事项已处理，未选optional不阻塞。语言项在wrap处理。不能以“本轮动作完成”直接跳过地图。

## 内容审核与带练数据

review的summary必须另含content_review；record不可写内容审核标记。示例结构（实际值必须来自当前全文）：

```json
{
  "content_review": {
    "status": "checked",
    "dimensions": {
      "center": "意图与正文的具体对应",
      "materials": "材料支撑与取舍的具体依据",
      "paragraphs": "主要段落的任务及重复或推进",
      "order": "读者获得信息的顺序及关系",
      "ending": "结尾怎样回应中心"
    },
    "priority": "最优先事项、理由及作者已有取舍",
    "pending_choices": ["P1"],
    "checked_version": "",
    "checked_sha256": ""
  }
}
```

checked为完成检查但尚有内容待处理；ready为可进入词句，要求pending_choices为空且必要／已选内容项已处理。绑定字段由review写入，不能通过record、复制旧标记或refresh绕过；wrap与next --cleanup检查当前稿绑定。初稿未完整时继续record，不制造全文审核。历史记录可读，不批量伪造旧完成标记；旧篇继续检阅时再补实际审核。

进入practice的summary或record须显式提供teaching对象，以下字段均为非空字符串：source、mechanism、example_type、example、comparison、application、check。example_type仅book_summary／book_quote／original_comparison。内容依教学规则，不可用占位文字完成机械校验。R01展示内容审核标记、依据和教学内容；用户不填写这些后台字段。


## 其他记录与兼容

原摘要字段保留：objective、why、method、steps、output、stop、stage、training_complete、selected_version、outcome（before/after/benefit/tradeoff/takeaway）、next_action、decisions、assistance、evidence_limit、learner_reflection、base_version、version_notes、process_note、completion_summary。overview、remaining仅兼容旧记录，新地图不再重复展示它们。stage由AI明确选择plan/practice/wrap；compare由submit产生，closed由close产生。本人心得不代填。

本轮教学展开在why、steps、stop、process_note；地图保存全局范围。version_notes每项含from_version、to_version、content，两端须已提交；详细文字变化与取舍只展开一处，不把同版修改伪装成新版本对照，不凭提交顺序推断教学因果。完成后completion_summary简述结果，地图记处理证据，assistance／evidence_limit集中说明帮助与边界。decisions只保留有效选择和背景；已结束页隐藏process_note，工具不判断自然语言中的过时结论，须按记录规则整理。

`refresh --input`仅接受completion_summary、decisions、process_note、version_notes、assistance、evidence_limit、outcome与training_map的说明文字。须回读、当前稿已提交且地图匹配；不可改变事项ID／等级／类型／结果状态、全文校对状态或稿件绑定，也不可改变阶段、采用稿和完成状态。无需重新submit／review／close；旧页照常备份，历史反馈不改。若要重判或继续修改文章，回到正常练习流程，不用整理命令跳过检验。

同版新文字提交后，旧outcome和指向当前版的version_notes保留为pending_result，页面标待复核；review须显式给outcome，若有旧version_notes也给更新后完整数组，仍成立的保留，不适用的撤下。不能只更新地图或哈希跳过成果核验。工具自动保护旧反馈及快照。

旧无地图练习不强制迁移已结束历史；明确继续时在实际最新稿review中加入training_map，首次加入也用status --read取得凭据。不得根据今天的新标准补写当时做过的事。旧无archive_key的快照仍可读。采用较早版本时使用该稿对应反馈中的地图，清掉较后稿的小结、当前意见和对照基准；历史版本收益仍按各自版本保留，不能套成采用稿收益。

next的basis和reason保存阶段建版决定；工具不根据字数、问题数或方法编号自动增版，是否值得保留阶段由AI依[记录规则](规则/记录.md)判断，用户覆盖。每个版本附简短目标，后台快照继续保护同版往返。

并发变化、事务残留或双方都改时先核对，不盲删文件。当前稿未提交的新修改列为pending_drafts，不算损坏；较早稿或已结束稿改变须保留并调查。后台状态在 `.writing-practice/状态`，稿件快照在 `.writing-practice/稿件恢复.zip`，每篇旧记录在 `.writing-practice/记录备份/<ID>.zip`。用户日常不操作隐藏目录；备份或搬迁整个练习目录时一并保留。

## 操作未完全成功时

保存与首页刷新是两件事。返回 `index: pending` 及 warning 表示练习已保存、只有导航待修复；先用返回的 ID 回读，核对开始页后只重试 index，不能重做 new、next 或 review。显式 index 失败不会改动练习内容。首页的“正在写”区域与“已结束的练习”折叠块由工具维护，其他说明保留；标题锚点丢失时先核对页面，不整页覆盖。

遇到读取后变更，重新读取并合并用户新内容；不循环提交旧数据。检测到缺核心目录或旧布局时先找回／迁移原目录，不创建空目录替代。选题库缺失不妨碍直接开练；用户要维护选题库时才用模板补建。
