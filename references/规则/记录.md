# 记录：过程跟着文章走

## 文件分工

| 位置 | 唯一职责 |
| --- | --- |
| 01 开始练习.md | 简短使用说明、当前正文与记录入口、折叠的已结束作品；不复制各篇成果 |
| 02 选题库.md（可选） | 备选题目与材料出处；已选条目链接练习，不再维护进度 |
| 03 练习方法.md | Skill 菜单的展示页；内容不独立维护，允许 Obsidian 调整表格空格 |
| 00 我的练习／ID 题目／R01 练习记录.md | 本篇地图、当前行动、反馈、版本收益和本人心得；不放全文 |
| 同项目 V 稿件 | 本人正文或本次约定的实际产物；不加教学日志 |
| 隐藏 .writing-practice | 目录身份、集中状态、稿件快照与记录备份，由工具维护 |

状态和采用版本以集中状态与实际稿件为准，不凭最大编号猜测。备份／搬迁整套练习时包含隐藏目录。开发测试、教学与工作流复盘保存在练习目录及 Skill 外，不新建项目 R02、集中写作档案、用户 AGENTS.md 或可见维护目录。

## R01 留什么

进行中依次呈现当前稿、目的与应保留之处、全文地图、当前动作和停止条件。依据及详细反馈折叠；已结束时突出成果，折叠最终地图，带遗留结束仍显示遗留。旧无地图记录不批量补写历史，明确继续时才按最新全文建图。

地图只维护一份，事项编号稳定；完成一个动作不删除其他项。诊断、检验和最终校对均更新此图，具体分级见诊断规则。约定在 why 说明书中工具与本文关系、steps 写本人任务、stop 写可观察标准；process_note 留当前必要解释与示例。

可选项的推荐程度、预期收益和保留原文的主要取舍，简写在地图现有 action（处理方向）中，使用户选择前可见；详细依据仍用 basis，当前动作的解释沿用 why／process_note，不增字段、表格列或独立报告。复核时按最新稿更新推荐与取舍；不把预期收益写成实际成果，也不回填已结束练习的历史判断。

成果说明实际对照版本、可观察的本人动作、具体文字变化、收益与代价。收到新稿只能确认文字变化，不能仅凭提交先后写成“在AI提示后重写／掌握”；沿用旧稿、回放测试等已知背景在小结说明，不另设问卷或要求每次证明来源。改动超出约定时仍检验目标效果，其他变化按全文取舍说明，不全归功于当前方法。

小结用两三句交代结果；地图result只留一处证据或选择，详细前后变化集中在version_notes，同一收益不在各区重复展开。basis只写方法机制或语言依据，不夹带“本遍发现”等进度；共同依据保持同文，工具合并展示，各项check仍保留独有标准。帮助程度与未检验部分集中一次；不同版本的帮助若有差别，按版本保留，不为去重抹掉差异。本人心得原样保留、不代填。

decisions只留仍有用的本人选择、来源与约束，不累加“等修改／待确认结束”等瞬时状态；状态由工具展示，当前解释用process_note。结束前清掉已过时的等待说明，重要取舍移入对应版本记录或decisions；已结束页不展示当前教学说明。已结束记录的文字纠错依工具使用的refresh整理，不重开、不增版，不改旧反馈来伪造历史。

每轮判断前 `status --read`，每轮检验后随 `review` 更新地图；只讨论且无结果变化无需写入。初诊及每轮检验后的回复给出实际R01练习记录的可点击入口，并说明本轮更新了什么、下一步在哪里做；首次说明这里保存整篇训练地图与进度，不能用“记录已保存”代替入口。凭据和快照保护操作见工具使用，不用字段齐全冒充已经理解全文。页面被用户手改时先理解并合并，不直接覆盖。

## 版本：按修改阶段主动判断

AI 说明“为什么保留此刻、下一轮主要改什么”，再准备工作稿；不要求新用户主动了解版本机制。用户明确沿用／新建优先，地图事项和版本不一一对应。

- 初稿未完整：继续 V01；已有完整稿且开始实质结构、材料或表达修改：保留完整稿，按下面的交接条件准备新版；已有本阶段工作稿或本人明确沿用时不重复建版。
- 同轮往返、补充、小修或顺带解决其他事项：继续当前 V。换方法、完成一项或收到反馈不自动增版。
- 内容确定后开始一组全文词句修改：保留内容定稿，在交给本人修改前主动建立校对工作版，不等本人要求。多处标点、搭配、句子主干或语序需要集中处理，即属新阶段，不能因每处改动短就统称“小修”而沿用内容版。只有一两处笔误、标点或简单顺句可沿用，并简述理由；未发现问题或仅有尚未选择的可选项时不预建。已有本轮校对工作版就继续使用，内容阶段的工作版不等于校对工作版；本人明确沿用的选择仍优先。
- 只讨论、看例子或保留原文不建版；不固定三版，不为版本好看补改动。

从讨论交接到改稿的时点：本人已承接修改方向，材料足够支撑本轮尝试，AI准备要求重写段落、调整顺序或补入重要材料时，就在当轮按上述条件判断并准备工作版本，不等本人提出“新建版本”，也不等改完或确认合入全文后才建。说明保留哪版、本轮改什么，建成后给出工作稿链接并请本人在其中修改；已在本阶段工作稿中则明确沿用。尚在找材料、比较方向时可继续对话；材料够后不再默认要求“先在这里试写一段”。本人明确想先在对话试写时尊重选择，转入正式稿时再交接。准备工作版本只复制当前稿，不代表获准把对话候选自动合入。

常规阶段建版前保存并检阅当前稿与地图，再用 `next --basis phase` 原样复制；本人明确要求另存用 `--basis user` 并如实记理由，不借此宣称完成诊断。已结束篇只有本人明确继续才重开。新工作稿承接地图，等待实际修改后复核；词句阶段也以前一版为对照基准。

命名为 `V编号 简短说明.md`：V01 区分导入原稿与从空白起稿，后续描述主要动作，不预宣称收益。工具按 ID 和版本说明定位。选题来源、原稿导入及选题库移转依开练规则。

## 合入、误改与保护

对话中的尝试先作候选；本人明确采用并要求合入时原样写入，不夹带润色，也不重复确认。改完回读全文核验。

用户说改好了而当前稿未变，检查本项目其他版本。确认写错位置且当前工作稿还是未改副本，可归入当前稿，不新增版本；两边都改则保留两边，核对差异再决定。具体命令见工具使用。

同版新文字的旧成果须复核，不能仅换哈希或刷新页面就算完成。历史快照与反馈不覆盖。只刷新展示不重开、不改正文；采用较早稿时，不带入较后稿的小结和本轮意见。并发变化或事务残留先核对，不盲删文件。
